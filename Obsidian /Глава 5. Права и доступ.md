# 5. Права доступа

> [!info] Зачем это знать
> Права доступа — основа безопасности Linux. Без понимания этой темы невозможно администрировать сервер.

---

## Основы — rwx

Каждый файл и директория имеют три группы прав:

```
-rwxr-xr--
 ^^^^^^^^^
 |   |  |
 |   |  другие (others)
 |   группа (group)
 владелец (user)
```

**Права:**
- `r` — read — читать (4)
- `w` — write — писать (2)
- `x` — execute — выполнять (1)
- `-` — нет права (0)

**Первый символ:**
- `-` — обычный файл
- `d` — директория
- `l` — симлинк

---

## Числовая нотация

Каждая группа прав — сумма цифр:

```
r = 4
w = 2
x = 1

rwx = 4+2+1 = 7
r-x = 4+0+1 = 5
r-- = 4+0+0 = 4
--- = 0
```

**Частые значения:**

| Цифры | Права | Для чего |
|-------|-------|---------|
| 755 | rwxr-xr-x | директории |
| 644 | rw-r--r-- | файлы |
| 700 | rwx------ | приватные файлы |
| 600 | rw------- | приватные файлы |
| 777 | rwxrwxrwx | опасно — никогда на сервере |

## chmod — изменение прав

### Числовой способ
```bash
chmod 755 file
chmod 644 file.txt
chmod -R 755 /папка       # рекурсивно
```

### Буквенный способ
```bash
chmod u+x file            # добавить x владельцу
chmod g-w file            # убрать w у группы
chmod o=r file            # установить только r для других
chmod u+x,g-w,o=r file   # несколько изменений сразу
chmod +x file             # добавить x всем
```

### По образцу
```bash
chmod --reference=file1 file2   # дать file2 права как у file1
```

### stat — посмотреть права в числовом виде
```bash
stat file.txt
# Access: (0755/-rwxr-xr-x)
```

---

## Права на директории — важно

На директориях права работают иначе:

| Право | Что даёт |
|-------|---------|
| `r` | видеть список файлов (`ls`) |
| `w` | создавать и удалять файлы внутри |
| `x` | войти в директорию (`cd`), обращаться к файлам |

> [!tip] Главное правило
> `x` на директории — это ключ от двери. Без него `r` и `w` бесполезны.
> Без `x` ты не можешь войти и не можешь обратиться к файлам внутри — даже если знаешь их имена.

**Права в ls -l:**
```bash
ls -l /папка    # без x — видишь имена но не метаданные
ls -ld /папка   # посмотреть права самой директории
```

## chown и chgrp — изменение владельца

### chown
```bash
sudo chown kinoresh file.txt           # сменить владельца
sudo chown kinoresh:group file.txt     # сменить владельца и группу
sudo chown -R kinoresh:group /папка    # рекурсивно
```

### chgrp
```bash
sudo chgrp group file.txt      # сменить только группу
sudo chgrp -R group /папка     # рекурсивно
```

## find + chmod — практика

```bash
# файлам одни права, директориям другие
find /папка -type f -exec chmod 644 {} \;
find /папка -type d -exec chmod 755 {} \;
```

- `{}` — место куда подставляется каждый найденный файл
- `\;` — конец команды exec

## Специальные биты

### SUID — Set User ID (4)

Программа запускается от имени **владельца файла**, а не пользователя который запустил.

```bash
ls -l /usr/bin/passwd
# -rwsr-xr-x root root
```

`s` вместо `x` у владельца — это SUID.

```bash
chmod 4755 file    # числом
chmod u+s file     # буквой
```

> [!warning] Безопасность
> SUID — потенциальная уязвимость. Если программа с SUID имеет уязвимость — злоумышленник может выполнить код от имени root (privilege escalation).

Найти все файлы с SUID:
```bash
find / -perm -4000 -type f 2>/dev/null
```

### SGID — Set Group ID (2)

**На файле** — запускается от имени группы владельца.

**На директории** — все новые файлы автоматически наследуют группу директории.

```bash
chmod 2755 /папка    # числом
chmod g+s /папка     # буквой
```

> [!tip] Реальный сценарий
> Команда разработчиков работает в одной папке. SGID на папке — все файлы автоматически принадлежат группе `devteam`. Никто не забудет сменить группу вручную.

### Sticky Bit (1)

Файл внутри директории может удалить только его **владелец** — даже если у других есть `w` на директорию.

```bash
ls -ld /tmp
# drwxrwxrwt   ← t в конце — sticky bit
```

```bash
chmod 1755 /папка    # числом
chmod +t /папка      # буквой
```

### Таблица специальных битов

| Бит | Цифра | Буква | Применяется |
|-----|-------|-------|-------------|
| SUID | 4 | u+s | файлы |
| SGID | 2 | g+s | файлы и директории |
| Sticky | 1 | +t | директории |

## Umask — права по умолчанию

Определяет права для новых файлов и директорий.

```bash
umask        # посмотреть текущий umask
umask 022    # установить umask
```

**Формула:**
```
файл:    666 - umask = финальные права
папка:   777 - umask = финальные права

Пример (umask 022):
файл:    666 - 022 = 644
папка:   777 -022 = 755
```

---

## chattr — атрибуты файловой системы

Защита файла на уровне файловой системы. Даже root не может изменить файл с атрибутом `+i`.

```bash
sudo chattr +i file.txt    # сделать файл неизменяемым
sudo chattr -i file.txt    # снять защиту
lsattr file.txt            # посмотреть атрибуты
```

## Вопросы на собеседовании

**"Что означает chmod 755?"**
→ владелец rwx, группа r-x, другие r-x. Стандарт для директорий.

**"Чем отличается x на файле от x на директории?"**
→ На файле — право запустить. На директории — право войти и обращаться к файлам внутри.

**"Что такое SUID и почему это опасно?"**
→ Программа запускается от имени владельца. Опасно если программа имеет уязвимость — можно получить права root.

**"Зачем нужен Sticky Bit?"**
→ Защищает файлы в общих директориях — удалить файл может только его владелец. Пример — /tmp.

**"Как работает umask?"**
→ Вычитается из базовых прав (666 для файлов, 777 для папок) и даёт финальные права новых файлов.
