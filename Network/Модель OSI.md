# 1. Модель OSI

> [!info] Зачем это знать
> OSI — эталонная модель для понимания как работают сети. Универсальный язык для описания любого сетевого процесса. На собесах спрашивают часто — и базово ("назови уровни"), и глубоко ("почему TCP на 4м, а не на 3м?").

---

## Что такое OSI

OSI (Open Systems Interconnection) — эталонная семиуровневая модель, разработанная ISO в **1984 году**. Описывает как данные передаются по сети, разбивая процесс на 7 независимых уровней. Каждый уровень отвечает только за свою задачу и взаимодействует только с соседними уровнями.

**Ключевые принципы модели:**
- Каждый уровень выполняет строго определённую функцию
- Уровни независимы — можно заменить реализацию одного уровня, не трогая остальные
- Каждый уровень предоставляет сервис вышестоящему и использует сервис нижестоящего
- Одноимённые уровни на двух хостах общаются друг с другом через **виртуальный канал** (логически), а реально данные идут вниз → по физике → вверх

> [!tip] Аналогия
> Отправка письма: пишешь текст → вкладываешь в конверт → пишешь адрес → несёшь на почту → почта грузит в грузовик → везут → получатель разбирает. Каждый этап — отдельный уровень, каждый не знает деталей других.

## Каждый уровень подробно
### Уровень 1 — Физический (Physical)

**Задача:** передать поток битов (0 и 1) через физическую среду.

**Что происходит:**
- Определяет электрические/оптические/радиосигналы для 0 и 1
- Управляет напряжением, временем сигналов, физическими разъёмами
- Не знает что в битах — просто передаёт

**Устройства:** хаб (hub), повторитель (repeater), кабели, сетевые карты (на физическом уровне)

**Типичные вопросы на собесе:**
- *"Чем хаб отличается от свитча?"* — Хаб работает на L1 и просто размножает сигнал на все порты. Свитч работает на L2 и умно направляет фреймы по MAC-адресу.

---

### Уровень 2 — Канальный (Data Link)

**Задача:** надёжная передача данных между двумя **непосредственно соединёнными** узлами. Работает внутри одной сети (LAN).

**Что происходит:**
- Разбивает данные на **фреймы**
- Добавляет **MAC-адреса** (откуда и куда в пределах LAN)
- Обнаруживает ошибки передачи (CRC-чексумма в конце фрейма)
- Управляет доступом к среде (CSMA/CD в Ethernet)

**Два подуровня:**
- **LLC (Logical Link Control)** — управление потоком, обнаружение ошибок
- **MAC (Media Access Control)** — MAC-адреса, доступ к среде

**Устройства:** коммутатор (switch), сетевая карта (NIC), Wi-Fi точка доступа

**MAC-адрес:** 48 бит = 6 байт, пишется как `AA:BB:CC:DD:EE:FF`. Первые 3 байта — **OUI** (идентификатор производителя), последние 3 — уникальный номер устройства. Прошит в железе, но можно менять программно.

**ARP живёт здесь:** ARP (Address Resolution Protocol) — протокол, который по IP-адресу узнаёт MAC-адрес. Технически работает на стыке L2/L3.

> [!warning] Частый вопрос
> *"Зачем нужны и MAC, и IP адреса?"* — MAC для доставки внутри LAN (не меняется при переходе между сетями), IP для маршрутизации между сетями (меняется с каждым хопом). Каждый роутер на пути меняет MAC-адреса в фрейме, но IP-адреса источника/назначения остаются прежними.

---

### Уровень 3 — Сетевой (Network)

**Задача:** **маршрутизация** — доставка пакетов между разными сетями. Логическая адресация.

**Что происходит:**
- Добавляет **IP-адреса** (источник и назначение)
- Роутер смотрит на IP и решает куда передать пакет дальше
- Фрагментация пакетов если MTU слишком маленький

**Устройства:** маршрутизатор (router), L3-switch

**Протоколы маршрутизации:**
- **OSPF** — внутри одной автономной системы (IGP)
- **BGP** — между автономными системами в интернете, "протокол интернета"

> [!info] Подробнее об IP-адресации
> В заметке [[2. IP-адресация и маски подсетей]] — маски, подсети, CIDR, всё это.

---

### Уровень 4 — Транспортный (Transport)

**Задача:** **сквозная** доставка данных между приложениями (не хостами — а именно приложениями через порты).

**Что происходит:**
- Сегментирует данные на куски
- Добавляет **порты** (source port, destination port) — чтобы знать какому процессу отдать данные
- **TCP** — надёжно, с подтверждениями, с контролем потока
- **UDP** — быстро, без гарантий

**Порты:**
- 0–1023 — системные (well-known): HTTP=80, HTTPS=443, SSH=22, DNS=53, FTP=21
- 1024–49151 — зарегистрированные
- 49152–65535 — динамические (эфемерные), используются как source port клиентом

> [!info] Подробнее
> Всё про TCP, UDP, handshake, flow control — в заметке [[4. TCP и UDP]]

---

### Уровень 5 — Сеансовый (Session)

**Задача:** управление **сессиями** — установка, поддержание, завершение диалога между двумя узлами.

**Что происходит:**
- Открывает сессию когда нужно начать обмен
- Синхронизирует (checkpoint'ы — если передача прервалась, можно продолжить с точки)
- Закрывает сессию когда обмен завершён

**Реальность:** В TCP/IP стеке этот уровень практически растворён в транспортном и прикладном. На практике редко явно упоминается, но концепция важна.

**Примеры:** когда ты логинишься на сайт — устанавливается сессия. Когда выходишь — сессия закрывается.

---

### Уровень 6 — Представления (Presentation)

**Задача:** **трансляция данных** — привести данные к формату, понятному приложению. Шифрование, сжатие, кодирование.

**Что происходит:**
- Шифрование/дешифрование ([[6. TLS и SSL|TLS]])
- Кодирование символов (ASCII → UTF-8)
- Сжатие данных
- Форматирование (JPEG, MP4, JSON)

**Реальность:** Как и сеансовый, в TCP/IP стеке встроен в прикладной уровень. TLS, например, формально работает между L4 и L7.

---

### Уровень 7 — Прикладной (Application)

**Задача:** **интерфейс** между сетью и пользовательскими приложениями. Протоколы верхнего уровня.

**Что происходит:**
- HTTP/HTTPS — веб
- DNS — разрешение имён → [[3. DNS]]
- [[7. SSH|SSH]] — удалённый доступ
- SMTP/IMAP/POP3 — почта
- FTP/SFTP — передача файлов
- SNMP — мониторинг сети
- DHCP — выдача IP → [[10. DHCP]]

> [!warning] Важно
> Прикладной уровень OSI — это **не сами приложения** (браузер, терминал). Это протоколы, которые приложения используют для общения по сети.

## Инкапсуляция и Декапсуляция

При **отправке** данные идут **сверху вниз** — каждый уровень добавляет свой заголовок (header). Это **инкапсуляция**.

При **получении** данные идут **снизу вверх** — каждый уровень снимает и обрабатывает свой заголовок. Это **декапсуляция**.

```
ОТПРАВИТЕЛЬ                              ПОЛУЧАТЕЛЬ
─────────────────────────────────────────────────────
[7] Данные                      ──>     [7] Данные
[6] [H6] | Данные               ──>     [6] [H6] | Данные
[5] [H5][H6] | Данные           ──>     [5] [H5][H6] | Данные
[4] [TCP HDR][H5][H6] | Данные  ──>     [4] [TCP HDR][H5][H6] | Данные
[3] [IP HDR][TCP]... | Данные   ──>     [3] [IP HDR][TCP]... | Данные
[2] [ETH HDR][IP]... | FCS      ──>     [2] [ETH HDR][IP]... | FCS
[1] 010110101010...              ──>     [1] 010110101010...
```

**PDU (Protocol Data Unit)** — как называется "пакет данных" на каждом уровне:

| Уровень | PDU |
|---------|-----|
| 7–5 | Данные (Data) |
| 4 | Сегмент (TCP) / Датаграмма (UDP) |
| 3 | Пакет (Packet) |
| 2 | Фрейм (Frame) |
| 1 | Биты (Bits) |

> [!tip] Как запомнить PDU
> **Д**евочки **Д**елают **П**одарки **Ф**инским **Б**ратьям
> Данные → Данные → Пакет → Фрейм → Биты (сверху вниз)

## OSI vs TCP/IP

В реальности интернет работает по модели **TCP/IP** — OSI это теория, TCP/IP это практика.

| OSI (7 уровней) | TCP/IP (4 уровня) | Примеры |
|-----------------|-------------------|---------|
| Прикладной (7) | Прикладной | HTTP, DNS, SSH, FTP |
| Представления (6) | Прикладной | TLS, UTF-8 |
| Сеансовый (5) | Прикладной | Сессии в HTTP |
| Транспортный (4) | Транспортный | TCP, UDP |
| Сетевой (3) | Интернет | IP, ICMP |
| Канальный (2) | Сетевого доступа | Ethernet, Wi-Fi |
| Физический (1) | Сетевого доступа | Кабели, сигналы |

**Почему TCP/IP победил:**
- Появился раньше OSI (ARPANET)
- Проще — меньше уровней
- Уже был реализован и работал

**Почему OSI до сих пор учат:**
- Универсальный язык — "проблема на L3" понятна всем
- Полезен для диагностики ("пингуется? значит L3 работает, смотрим L4")

## Устройства по уровням OSI

| Устройство | Уровень | Что умеет |
|------------|---------|-----------|
| Повторитель (Repeater) | L1 | Усиливает сигнал, не понимает биты |
| Хаб (Hub) | L1 | Рассылает всё всем портам |
| Свитч (Switch) | L2 | Направляет фреймы по MAC-таблице |
| Маршрутизатор (Router) | L3 | Маршрутизирует пакеты по IP |
| L3-Switch | L2+L3 | Свитч + маршрутизация между VLAN |
| Файрвол (Firewall) | L3–L7 | Фильтрует трафик → [[11. Firewall и iptables]] |
| Балансировщик нагрузки | L4/L7 | Распределяет трафик → [[13. Балансировка нагрузки (basics)]] |

## Switch vs Router — детально

| | Switch (коммутатор) | Router (маршрутизатор) |
|--|---------------------|------------------------|
| Уровень OSI | L2 (канальный) | L3 (сетевой) |
| Адресация | MAC-адрес | IP-адрес |
| Где работает | Внутри одной сети (LAN) | Между разными сетями |
| Таблица | MAC-таблица (MAC → порт) | Таблица маршрутизации (сеть → интерфейс) |
| Broadcast | Рассылает broadcast всем | Не пропускает broadcast между сетями |
| Пример | Устройства в одном офисе | Подключение к интернету |

> [!tip] Аналогия
> **Switch** — охранник в офисе, знает всех сотрудников по лицу (MAC), направляет внутри здания.
> **Router** — почтальон, знает адреса домов (IP), доставляет между городами, не знает кто живёт внутри.

## Диагностика по уровням OSI

Когда что-то не работает — проверяй снизу вверх:

| Уровень | Инструмент | Что проверяем |
|---------|-----------|---------------|
| L1 | Смотришь глазами | Кабель воткнут? Моргает ли индикатор? |
| L2 | `arp -a`, `ip link` | Есть ли MAC в ARP-таблице? |
| L3 | `ping`, `ip route`, `traceroute` | Доходят ли пакеты? Правильный маршрут? |
| L4 | `netstat`, `ss`, `telnet host port` | Открыт ли порт? Устанавливается TCP? |
| L7 | `curl`, браузер, `dig` | Отвечает ли приложение? Правильный HTTP код? |

> [!tip] Золотое правило диагностики
> Если `ping` до сервера работает (L3 ок), но `telnet host 80` не работает (L4 проблема) — значит порт закрыт или процесс не слушает. Сужай проблему уровень за уровнем.

## Частые вопросы на собесе

> [!question] "Назови 7 уровней OSI"
> Физический → Канальный → Сетевой → Транспортный → Сеансовый → Представления → Прикладной (снизу вверх)

> [!question] "Чем отличается OSI от TCP/IP?"
> OSI — теоретическая модель с 7 уровнями. TCP/IP — практический стек с 4 уровнями, где уровни 5, 6, 7 OSI объединены в один прикладной. Реальный интернет работает по TCP/IP, OSI используется как концептуальный язык.

> [!question] "На каком уровне работает ping?"
> [[8. ICMP|ICMP]] (который использует ping) работает на **L3 (сетевом)**. Но для отправки ICMP пакета нужны L1 и L2. Сам ping — утилита прикладного уровня (L7), но протокол ICMP — L3.

> [!question] "Зачем нужен L2 если есть L3?"
> L3 (IP) умеет маршрутизировать между сетями, но не знает как физически передать данные в конкретном LAN-сегменте. L2 (Ethernet, MAC) решает "последнюю милю" — как доставить фрейм от роутера до конкретного устройства в локальной сети.

> [!question] "На каком уровне работает HTTPS?"
> HTTPS использует протоколы нескольких уровней: HTTP — L7, TLS (шифрование) — формально L6, TCP — L4, IP — L3. В TCP/IP модели всё это прикладной уровень.

> [!question] "Что такое PDU?"
> Protocol Data Unit — единица данных на каждом уровне. Биты (L1) → Фрейм (L2) → Пакет (L3) → Сегмент/Датаграмма (L4) → Данные (L5–L7).

> [!question] "Что происходит с MAC-адресом при прохождении через роутер?"
> Роутер на каждом хопе **перезаписывает MAC-адреса**: снимает старый фрейм (L2), смотрит на IP (L3), создаёт новый фрейм с MAC-адресом следующего хопа. IP-адреса источника и назначения при этом **не меняются** (если нет NAT → [[9. NAT]]).

> [!question] "Чем хаб отличается от свитча?"
> Хаб (L1) — тупо рассылает сигнал на все порты, все устройства видят весь трафик (collision domain = вся сеть). Свитч (L2) — учит MAC-адреса и отправляет фрейм только на нужный порт, каждый порт — отдельный collision domain.

> [!summary] Главное запомнить
> - **7 уровней снизу вверх:** Физический → Канальный → Сетевой → Транспортный → Сеансовый → Представления → Прикладной
> - **PDU:** Биты → Фрейм → Пакет → Сегмент/Датаграмма → Данные
> - **Инкапсуляция** — вниз (добавляем заголовки), **Декапсуляция** — вверх (снимаем)
> - **Switch** = L2 (MAC, внутри LAN), **Router** = L3 (IP, между сетями)
> - **OSI** = теория (7 уровней), **TCP/IP** = практика (4 уровня)
> - **MAC меняется** на каждом хопе, **IP остаётся** до конца (без NAT)
> - Диагностика всегда снизу вверх: L1 → L2 → L3 → L4 → L7
