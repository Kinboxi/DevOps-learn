# 6. Процеси

> [!info] Зачем это знать
> Процеси — основа Linux. Без розуміння цієї теми неможливо адмініструвати сервер і це топ-1 тема на співбесідах.

---

## Основні поняття

**Програма** — файл на диску. Набір інструкцій. Нічого не робить поки лежить.

**Процес** — програма яка запущена і виконується в пам'яті прямо зараз.

**Скрипт** — текстовий файл з командами. Коли запускаєш — bash читає і виконує. Теж стає процесом.

> [!tip] Аналогія
> Програма — це рецепт. Процес — це коли ти готуєш по цьому рецепту. Рецепт один, але можна готувати двічі одночасно — це два окремих процеси.

---

## Атрибути процесу

- **PID** — унікальний номер процесу
- **PPID** — номер батьківського процесу
- **TTY** — термінал до якого прив'язаний процес (`?` = демон)
- **RUID** — реальний користувач (хто запустив)
- **EUID** — ефективний користувач (від чийого імені виконується)

```bash
echo $$    # PID поточного bash
```

---

## Життєвий цикл процесу

### 1. fork() — створення
Батьківський процес створює точну копію себе. Дитина отримує новий PID.

### 2. exec() — завантаження
Дитина замінює себе новою програмою. PID залишається той самий.

### Повна картина запуску команди:
```
ти пишеш "ls"
    ↓
bash знаходить /usr/bin/ls через $PATH
    ↓
bash робить fork() → копія bash (новий PID)
    ↓
копія робить exec() → стає ls
    ↓
ls виконується → виводить файли
    ↓
ls викликає exit() → завершується
    ↓
bash читає статус через wait() → запис видаляється
```

### 3. Стани процесу:
```
Running  — виконується на CPU
Sleeping — чекає (диск, мережа, введення)
Stopped  — призупинений (Ctrl+Z)
Zombie   — завершився, чекає wait() від батька
```

### 4. exit() — завершення
Процес завершується. Ядро звільняє пам'ять, закриває файли, надсилає SIGCHLD батьку.

### 5. wait() — збирання
Батько читає код завершення дитини. Запис в таблиці процесів видаляється.

## Спеціальні типи процесів

### Демон
Процес який працює у фоні без прив'язки до терміналу. Запускається при старті системи. Чекає запитів.

```bash
ps aux | grep sshd    # TTY = ? → це демон
```

Приклади: `sshd`, `nginx`, `systemd`

> [!tip] Аналогія
> Охоронець який сидить біля дверей 24/7. Нічого не робить поки хтось не постукає.

### Зомбі-процес
Процес завершився але батько ще не викликав `wait()`. Не займає пам'ять але займає запис в таблиці процесів.

> [!tip] Аналогія
> Дитина зробила домашнє завдання і чекає поки батько перевірить. Поки не перевірив — стоїть поруч.

### Процес-сирота
Батьківський процес завершився раніше за дитину. Systemd (PID 1) автоматично усиновлює сироту. Процес продовжує працювати нормально.

---

## PID 1 — systemd
Перший процес який запускає ядро при завантаженні. Батько всіх процесів. Усиновлює сиріт.

---

## Потоки (threads)
Легкі процеси всередині процесу. Спільна пам'ять і файли.

> [!tip] Аналогія
> Процес — ресторан. Потоки — офіціанти всередині. Один ресторан, багато офіціантів, спільна кухня.

---

## Shell built-in vs executable

```bash
type cd     # cd is a shell built-in
type ls     # ls is /usr/bin/ls
```

- **Built-in** — вбудований в bash. Fork не відбувається.
- **Executable** — зовнішня програма. Bash робить fork + exec.

## Команди

### ps — список процесів
```bash
ps                      # процеси поточного терміналу
ps aux                  # всі процеси системи
ps -ef                  # всі процеси, інший формат
ps aux | less           # з пагінацією
ps aux --sort=%mem      # сортування по пам'яті
ps aux --sort=%cpu      # сортування по CPU
ps -ef --forest         # дерево процесів
ps -f -u username       # процеси конкретного користувача
```

**Що означає aux:**
- `a` — всі користувачі
- `u` — розширений формат
- `x` — процеси без терміналу (демони)

### pstree — дерево процесів
```bash
pstree                  # ієрархічне дерево
pstree -c               # без злиття однакових гілок
```

### pgrep — пошук процесу
```bash
pgrep -l sshd           # знайти процес по імені
ps -ef | grep sshd      # альтернатива
```

## top і htop — динамічний моніторинг

```bash
top          # динамічний список процесів в реальному часі
htop         # покращена версія top з кольорами
```

**Важливі колонки в top:**
- `PID` — номер процесу
- `USER` — власник
- `%CPU` — використання CPU
- `%MEM` — використання пам'яті
- `S` — стан (R=running, S=sleeping, Z=zombie)

**Load average** — навантаження за 1, 5, 15 хвилин. В нормі має бути нижче кількості ядер CPU.

**Колонки CPU в top:**
- `us` — user space — процеси користувача
- `sy` — system — ядро
- `wa` — I/O wait — чекає диску
- `id` — idle — простоює

## Сигнали і kill

Сигнал — це повідомлення яке ядро надсилає процесу.

```bash
kill PID              # надіслати SIGTERM (15) — ввічливе завершення
kill -9 PID           # надіслати SIGKILL — примусове вбивство
kill -15 PID          # те саме що kill PID
pkill firefox         # вбити по імені
killall firefox       # вбити всі процеси з таким іменем
pidof firefox         # знайти PID по імені
```

**Важливі сигнали:**

| Сигнал | Номер | Дія |
|--------|-------|-----|
| SIGTERM | 15 | ввічливе завершення, процес може проігнорувати |
| SIGKILL | 9 | примусове вбивство, не можна перехопити |
| SIGSTOP | 19 | призупинити процес |
| SIGHUP | 1 | перезавантажити конфігурацію |

> [!tip] Важливо
> SIGKILL не можна перехопити або проігнорувати. Ядро вбиває процес примусово.

## Фонові процеси

```bash
команда &             # запустити одразу у фоні
Ctrl+Z                # призупинити поточний процес
bg                    # відправити призупинений процес у фон
fg                    # повернути фоновий процес на передній план
fg %1                 # повернути конкретне завдання
jobs                  # список завдань поточного терміналу
```

**Послідовність для фону:**
```
запустив команду → Ctrl+Z (пауза) → bg (у фон) → продовжує працювати
```

**disown** — відв'язати процес від терміналу:
```bash
disown %1             # процес продовжить працювати після закриття терміналу
```

## Вопросы на собеседовании

**"Що таке процес?"**
→ Програма яка запущена і виконується в пам'яті. Має PID, стан, власника.

**"Що таке fork і exec?"**
→ fork — створює копію процесу. exec — замінює процес іншою програмою. Разом запускають будь-яку команду.

**"Що таке зомбі-процес?"**
→ Процес завершився але батько не викликав wait(). Не займає пам'ять але займає запис в таблиці.

**"Що таке демон?"**
→ Процес який працює у фоні без терміналу. TTY = ?. Приклади: sshd, nginx.

**"Що станеться якщо батьківський процес завершиться раніше за дочірній?"**
→ Дочірній стає сиротою. Systemd (PID 1) його усиновлює.

**"Чим kill відрізняється від kill -9?"**
→ kill надсилає SIGTERM — процес може завершитись коректно. kill -9 надсилає SIGKILL — ядро вбиває примусово, не можна перехопити.

**"Як відправити процес у фон?"**
→ Ctrl+Z щоб призупинити, потім bg. Або запустити одразу з &.

**"Що показує load average?"**
→ Середнє навантаження за 1, 5 і 15 хвилин. В нормі нижче кількості ядер CPU.
